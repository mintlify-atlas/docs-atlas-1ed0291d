MejoraGemeseg is a monorepo with a NestJS backend and a React + Vite frontend. The fastest way to get a fully functional local environment is to start PostgreSQL and Redis via Docker, then run the backend and frontend in separate terminals. The seed script creates all test users and sample projects automatically.

<Steps>

### Install prerequisites

You need the following tools before running anything:

- **Node.js 18 or later** — [nodejs.org](https://nodejs.org)
- **PostgreSQL 17** — installed locally, or via Docker (recommended below)
- **Docker** (optional but recommended) — [docker.com](https://docker.com)

<Tip>
  If you use the Docker path you do not need a separate PostgreSQL installation. Docker Compose spins up both `postgres:16-alpine` and `redis:7-alpine` for you.
</Tip>

### Start the database (Docker)

From the repo root, start PostgreSQL and Redis using the provided Compose file:

```bash
docker compose up -d db redis
```

This starts:
- **`gemeseg-postgres`** on `localhost:5432` — user `postgres`, password `postgres`, database `gemeseg`
- **`gemeseg-redis`** on `localhost:6379`

If you prefer a local PostgreSQL instance, create a database named `gemeseg` and update `DATABASE_URL` in the next step accordingly.

### Configure the backend environment

Copy the example environment file and fill in the required values:

```bash
cd backend
cp ../.env.example .env
```

Open `.env` and set at minimum:

```bash
NODE_ENV=development
PORT=3000
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/gemeseg?schema=public
REDIS_HOST=localhost
REDIS_PORT=6379
JWT_SECRET=your-jwt-secret          # any random string, keep it secret
FRONTEND_URL=http://localhost:5173
GITHUB_TOKEN=                        # optional — enables gpt-4o-mini AI chat
```

<Note>
  `GITHUB_TOKEN` is optional. Without it the AI chat falls back to a set of predefined mock responses. You can still use all other modules normally.
</Note>

### Install backend dependencies and run migrations

```bash
# still inside backend/
npm install
npx prisma migrate dev
```

Prisma reads `DATABASE_URL` from `.env`, applies all pending migrations, and generates the typed Prisma Client.

### Start the backend dev server

```bash
npm run start:dev
```

NestJS starts in watch mode. Once you see `Application is running on: http://[::1]:3000` the backend is ready.

- **API base:** `http://localhost:3000/api`
- **Swagger UI:** `http://localhost:3000/docs`
- **Health check:** `http://localhost:3000/health`

### Install and start the frontend

Open a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Vite starts on **`http://localhost:5173`**. The frontend reads `VITE_API_URL` from `frontend/.env` — if that file does not exist, create it:

```bash
# frontend/.env
VITE_API_URL=http://localhost:3000
```

### Verify everything is running

| Check | URL | Expected |
|-------|-----|----------|
| Backend health | `http://localhost:3000/health` | `{"status":"ok","timestamp":"..."}` |
| Swagger UI | `http://localhost:3000/docs` | Interactive API explorer |
| Frontend login | `http://localhost:5173` | GEMESEG login page |

Log in with `admin@gemeseg.com` / `gemeseg2026` to access the full admin panel, or use `admin@general.com` / `admin2026` to act as Super Admin across all tenants.

</Steps>
