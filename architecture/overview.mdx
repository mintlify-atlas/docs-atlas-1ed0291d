MejoraGemeseg is a **monorepo** containing a NestJS backend and a React frontend that are deployed independently but share a single Git history. The backend exposes a REST API consumed exclusively by the frontend; there is no GraphQL layer or separate microservice. All persistent state lives in a single PostgreSQL 17 database accessed through Prisma ORM.

## NestJS backend

The `AppModule` imports every feature module explicitly. There are no dynamic module registrations at runtime:

```typescript
// src/app.module.ts
@Module({
  imports: [
    ScheduleModule.forRoot(),
    CacheModule,
    AuthModule,
    UsersModule,
    ProjectsModule,
    TasksModule,
    AiModule,
    QueueModule,
    ToolsModule,
    AgentsModule,
    CompaniesModule,
    CacaoModule,
    PermissionsModule,
    CustodiasModule,
    PersonalModule,
    VentasModule,
    SistemasModule,
  ],
})
export class AppModule {}
```

### Bootstrap configuration (`main.ts`)

Key settings applied at application startup:

- **Global API prefix:** all routes under `/api` (except `/health`, `/docs`, `/docs/*`)
- **Helmet:** enabled with `contentSecurityPolicy: false` and `crossOriginResourcePolicy: cross-origin`
- **CORS:** allows `FRONTEND_URL`, `https://app.gemeseg.com`, `https://mejora-gemeseg.web.app`, `https://mejora-gemeseg.firebaseapp.com`, Firebase preview channels (`mejora-gemeseg--<channel>-<hash>.web.app`), and all `http://localhost:*` in non-production environments
- **Global `ValidationPipe`:** `whitelist: true`, `forbidNonWhitelisted: true`, `transform: true`
- **Swagger:** mounted at `/docs`, title *"GEMESEG Admin API"*, version `1.0`
- **Static assets:** `public/` directory served at root (used for logo uploads via `uploads/logos/`)
- **Port:** reads `process.env.PORT`, defaults to `8080`

### PrismaService

`PrismaService` (in `src/prisma/`) is a singleton `@Injectable()` that extends `PrismaClient`. Every feature module injects it to query the database. Prisma is configured with `@prisma/adapter-pg` and targets `debian-openssl-3.0.x` and `linux-musl-openssl-3.0.x` binary targets for Railway and Cloud Run compatibility.

## React frontend

The frontend is a single-page application built with Vite. Routing is handled by `react-router-dom`; all route protection is done through two wrappers:

- **`ProtectedRoute`** — redirects to `/login` if no JWT is present in `localStorage`.
- **`SectionRoute`** — calls `usePerm().canView(section)` and redirects to `/dashboard` if the current user's company does not have the section enabled or if their `UserPermission` denies view access.

Axios is configured with a request interceptor that automatically attaches `Authorization: Bearer <token>` from `localStorage` to every outgoing request.
